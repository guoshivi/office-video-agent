# 房源表填写规范

一份表进来，程序要据此算月租、日均、工位数、人均——这些数字会直接念进视频。
写法不统一，程序只能猜；猜错比不报更糟，因为视频发出去收不回来。

所以规则只有一条：**能写成标准的就写成标准的，写不标准的宁可不写。**

## 一、租金列怎么写

| 你要表达的意思 | 这么写 | 程序的理解 | 180 平举例 |
|---|---|---|---|
| 每平每月 40 元（最常见） | `40` | 40 元/㎡/月 | 月租 7200 |
| 每平每天 3.5 元（写字楼常见） | `3.5元/平/天` | 3.5 元/㎡/天 | 月租 18900 |
| 每平每月 35，物业另收 5 | `35+5` | 两段相加，按 40 算 | 月租 7200 |
| 每平每月 40，已含物业/含税 | `40含物业`、`40含税` | 一口价，不再加 | 月租 7200 |
| 整层整月 2.8 万 | `2.8万/月`、`28000/月` | 整月总价 | 月租 28000 |
| 一间单间整月 900 | `900/月` | 整月总价 | 面积写「单间」也行 |
| 还没定 | `面谈`、`价格咨询房东` | 不算钱 | 不报价 |

**不要写**：把格局、朝向、楼层填进租金列（比如 `3+1`、`朝南`）。程序会老老实实当钱算。

### 裸数字是怎么判的

表里 657 条只写了 `40`、`26` 这样的一串数字，没写单位。程序按顺序试三种读法，
谁的单价落在 **8~800 元/㎡/月** 就采用谁：

1. 元/㎡/月 —— `40` × 面积，单价 40，合理，采用
2. 元/月（整月总价）—— `900` 当总价，180 平折 5 元/㎡/月，低于 8，不采用
3. 元/㎡/天 —— `3.5` 当单价天，折 105 元/㎡/月，合理，采用

三种都不落在区间里，就**不报价**（比如 `318万` 挂在 472 平上，折出 6737 元/㎡/月，
明显不是月租）。跳过价格的房源照常出片，只是不说钱。

## 二、面积列怎么写

**必须写数字，单位写「平」也没关系**：`180`、`180平`、`180㎡` 都认。

写成 `单间`、`店面`、`可选`、`可定制`、`毛坯` 的，面积算不出来，于是：

- 工位数（面积 ÷ 8）、人均月租跟着算不出
- 「一天多少钱」「人均多少」这两句话不出
- 租金要是写了 `900包物业` 这种带「含/包」的整月价，仍然能报「一个月 900」

## 三、别的列

| 列 | 规范 | 影响 |
|---|---|---|
| 区域 / 楼栋 / 房号 | 三列分开填，不要挤在一格 | 钩子里的「在{区域}」「{面积}平这个面积」靠它 |
| 隔间 | 写 `3隔`、`3+1` 都行，原文保留 | 口播里的格局 |
| 朝向 | `东南`、`南` | 「采光」类句子 |
| 看房备注及中介费 | 中介费、钥匙、联系人写在备注里，**不要写进租金** | 审核时给人看，不进视频 |
| 家具/装修 | 表头以「家具」开头即可 | 「拎包入驻」类句子 |

## 四、改完怎么自检

```bash
python tools/rent_audit.py --list 20
```

输出会说清楚：多少条能算出月租、每条按什么口径算的、哪些判不出来以及原因。
月租最高的三条也会列出来——**这三条一定是真房源**，如果出现「一天五万六」，
说明那一行填错了列，按上面的表改。

## 五、为什么不做成「导入时自动纠正」

可以做，但不该做。程序猜错一个数字，视频里就念出一个错价格，中介拿去带看要赔上信誉；
程序拒绝报价，最多少一句卖点语。所以这里的取舍是**宁可少说，不说错**。
规范 + 体检报告，比自动纠正可靠。
