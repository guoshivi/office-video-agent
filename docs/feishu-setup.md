# 接入飞书

有两种用法，**业务能力完全一样**（同一个任务服务、同一套口播与出片逻辑），
区别只在「谁去收消息」：

| | 方案 A：WorkBuddy 通道 | 方案 B：独立机器人 |
| --- | --- | --- |
| 要不要建企业自建应用 | 不用 | 要 |
| 电脑上必须开着什么 | WorkBuddy | 只要本服务在跑 |
| 谁在飞书里回话 | WorkBuddy 里的 Agent | 项目自带的 `app/feishu` |
| 上手成本 | 几步就能用 | 建应用 + 开权限 + 发布审核 |
| 适合 | 先在朋友电脑上跑通、自己用 | 正式交付，无人值守 |

---

## 方案 A：WorkBuddy 飞书通道（推荐先走这条）

WorkBuddy 已经把他的飞书接好了，那就**不再单独建机器人**：
飞书里的消息由 WorkBuddy 的 Agent 接住，Agent 调本地服务干活，再把结果回给你。

### 为什么这样做不会重复实现

所有入口（WebUI 上传、WorkBuddy 桌面、飞书、以后的微信）都收敛到同一组接口：

```
POST /api/channel/clips                 收下视频，先存着
POST /api/channel/clips/{id}/bind       说房源，绑定并生成口播
POST /api/tasks/{id}/render             出片
GET  /api/tasks/{id}                    看进度
```

「先发视频、过一会儿才说房号」这种真实节奏，靠 `channel_clips` 这张表兜住：
视频先落进 `data/inbox/`，房源确认后才建任务，中间不会丢素材。

### 对话怎么走

在飞书里（或直接在这台电脑的 WorkBuddy 里）说：

| 你说 | 背后发生什么 |
| --- | --- |
| 发一段办公室视频 | `ova send` 落盘，回复「已收到，请回复房源」 |
| `A区 中关村大厦 1201` | `ova bind` 精确匹配 → 建任务 → 回任务号 + 口播草稿 |
| `102`（只报房号且重号） | 回 3 个候选让你选，选完再绑定 |
| `改口播 开头别提面积` | `ova script --set` 覆盖草稿 |
| `出片` | `ova render --wait`，3–6 分钟后回成片路径 |

命令行工具就是 `tools/ova.py`，WorkBuddy 侧的技能文件在
`D:\luo\.workbuddy\skills\office-video-channel\SKILL.md`，它规定了
「歧义必须让人选、出片前先确认口播」这些不能越过的规则。

### 前提条件

1. 本服务在跑：`start.bat`，默认 <http://127.0.0.1:8770>。
2. 朋友电脑上装了 WorkBuddy 并登录，而且**开着**。这是方案 A 唯一的硬约束——
   它没有常驻进程托管，WorkBuddy 关了，飞书那边就没人接。
3. 视频工作台可访问（`/api/workbench/status` 里 `online: true`）。

一旦你希望「关掉 WorkBuddy 也能收消息」，再走方案 B，代码已经写好了，
只差把应用凭据填进 `.env`。

### 自己先验一遍

```bash
cd /d/luo/office-video-agent
.venv/Scripts/python.exe tools/ova.py status
.venv/Scripts/python.exe tools/ova.py send  D:\某段实拍.mp4
.venv/Scripts/python.exe tools/ova.py bind  "F区 F14 202-2"
.venv/Scripts/python.exe tools/ova.py render V20261101-ABCDE --wait
```

## 方案 B：独立机器人

用**企业自建应用 + 长连接**接收飞书消息，不依赖公网 IP、不需要内网穿透。
下面的「一」到「十」都是这个方案。

> 如果两个用途共用一个应用，飞书会把同一条消息随机派给其中一条长连接，
> 事件会丢一半，所以方案 B 必须单独建应用。

## 一、创建应用（3 分钟）

1. 打开 <https://open.feishu.cn/app>（用朋友公司的飞书账号登录）。
2. 「创建企业自建应用」，名称填「房源视频助手」，图标随意。
3. 进入应用 →「凭证与基础信息」，复制 **App ID** 和 **App Secret**。

填到本项目的 `.env`：

```
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## 二、开启机器人能力

应用详情 →「添加应用能力」→ 添加**机器人**。

## 三、开通权限

「权限管理」→ 搜索并开通以下权限：

| 权限码 | 用途 |
| --- | --- |
| `im:message` | 接收用户发来的消息与视频 |
| `im:message:send_as_bot` | 以机器人身份回复口播、进度、成片 |
| `im:resource` | 下载消息里的视频、上传成片 |
| `im:chat` | 读取群信息（把机器人拉进群时必需） |
| `bitable:app` | 读写多维表格（不使用表格可跳过） |

## 四、订阅事件并使用长连接

「事件与回调」→「事件配置」：

1. 订阅事件：**接收消息 `im.message.receive_v1`**。
2. 订阅方式：选择 **使用长连接接收事件**（不要选「将事件发送至开发者服务器」）。

这一步决定了 `app/feishu/bot.py` 能否直接收到消息。

## 五、发布版本

「版本管理与发布」→ 创建版本（填 1.0.0）→ 申请发布 → 让企业管理员在管理后台通过。
**没发布之前，长连接能建立但收不到消息**，这一步最容易漏。

## 六、把机器人用起来

- 单聊：飞书搜索「房源视频助手」→ 直接发视频。
- 群聊：群设置 → 机器人 → 添加该应用；群里需要 @机器人 才会触发。

## 七、多维表格（可选）

1. 新建一个多维表格，第一列（或任一文本列）命名为 **任务编号**。
2. 表格右上「⋯」→「添加文档应用」→ 添加刚创建的应用，权限选**可编辑**。
3. 从浏览器地址栏取两个 ID：

```
https://xxx.feishu.cn/base/BASCxxxxxxxxxxxx?table=tblYYYYYYYY
                             ^^^^^^^^^^^^^^^       ^^^^^^^^^^^
                             多维表格 App Token     table_id
```

4. 写入 `.env`：

```
FEISHU_BASE_APP_TOKEN=BASCxxxxxxxxxxxx
FEISHU_TASK_TABLE_ID=tblYYYYYYYY
```

本程序会按「任务编号」查重后写入/更新，字段缺失只会记日志，不会打断出片。

## 八、自检

```bash
# 在本机启动服务后
curl http://127.0.0.1:8770/api/feishu/status
```

`connected: true` 表示长连接已握手。WebUI「系统设置 → 飞书 Agent」也会显示状态，
旁边有「重连长连接」按钮，改完 `.env` 重启服务即可。

## 九、飞书里能用的指令

| 你说 | 机器人做什么 |
| --- | --- |
| 直接发一段视频 | 保存原片，并提示下一步补房源信息 |
| `A区 中关村大厦 1201` / 只发 `1201` | 绑定房源 → 生成口播草稿 → 回任务编号 |
| `出片 V20251101-ABCDE` | 提交视频工作台渲染，完成后把成片发回来 |
| `改口播 V20251101-ABCDE 新文案` | 覆盖口播草稿 |
| `状态 V20251101-ABCDE` / `状态` | 查单个任务或最近 5 条 |
| `房源 A区 100平 带家具` | 关键词检索在租房源（最多 5 条） |
| `帮助` / `取消` | 查看指令 / 放弃当前待处理视频 |

## 十、常见问题

- **连接失败 10003 / 403**：应用没发布，或订阅方式不是「长连接」。
- **能连上但没反应**：机器人没被拉进群；群里必须 @机器人。
- **下载视频 403**：缺 `im:resource` 权限，或该消息不是发给这个机器人的。
- **发送成片失败**：超过 30MB 时会降级为文本路径，属预期行为。
- **多维表格写入失败**：表里没有「任务编号」列，或没把应用加成表格协作者。
