# 文案钩子与成本句

文案里最值钱的不是卖点，是前 3 秒。抖音的流量基本由开头决定，开头留不住人，
后面剪得再好也没人看。所以这一层只干一件事：把第一句话写对。

代码分两块：`data/copy/hooks.json` 存话术，`app/hooks.py` 负责算数和筛模板。
改话术只动 JSON，不用碰代码，也不用重启服务（按文件修改时间自动重读）。

## 钩子库长什么样

```json
{
  "tier": "contrast",
  "tpl": "{area}平的办公室，一天只要{daily}元",
  "need": ["area", "daily"],
  "aud": ["startup"]
}
```

- `tpl` 里的 `{xxx}` 是房源变量，渲染前会检查是否齐全
- `need` 写清楚这条话术依赖哪些变量，纯粹给人看，实际以 tpl 里出现的为准
- `aud` 是适用人群，`any` 表示谁都能看

**变量不齐的模板会被整条跳过。** 宁可少一版，也不出「一天只要元」这种半截话。

## 三档话术

| 档 | 什么时候用 | 它在做什么 |
|---|---|---|
| 参数反差 | 面积、租金齐全，数字好看 | 打破「这么大一定很贵」的预判 |
| 痛点召唤 | 参数平庸，但格局、家具、位置好 | 先说老板正在难受的事，再给这套房当解药 |
| 稀缺时效 | 同价位竞品多，要抢客户 | 制造紧迫感，逼私信 |

稀缺档属于话术，不承载事实。用之前先确认真稀缺，编多了掉信任。

## 成本句：老板只听得懂「一天多少钱」

租金字段的写法太乱，`3.5元/平/天`、`2.8万/月`、`28000` 都有。统一折算：

```
月租 = 单价 × 面积 × 30        日均 = 月租 / 30
工位 = 面积 / 8（含公摊）       人均 = 月租 / 工位数
```

**最后有一道校验：折出来的单价必须在 8~800 元/平/月之间，否则整条成本句不出。**

这道校验不是洁癖。房源表里 `rent` 字段填错的（比如把「35+5 格局」写进租金），
硬算会得出「1600 平月租 168 万、一天五万六」，这种数字进视频就是事故。

## 人群

选「创业团队」时，只会出面向创业团队的话术，加通用的；选「不限人群」时只出
通用的——人群定向的话术对另一拨人来说是噪音（「团队扩到 15 个人」对找办事处的
外地老板毫无意义）。

同一套房源、同一个人群，每次出的顺序是稳定的（按房源内容做种子）。换房源才换
开头，这样中介才能对比哪版更好。

## 双平台标题

抖音靠前两秒决定划不划走，标题把面积和价格顶到最前面，上限 30 字。
小红书是搜索场，标题得能被「望京 办公室 出租」这种词搜到，上限 20 字。

两个平台各出三条，租金算不出来时自动退到不带价格的版本，不会空着。

## 前端在哪用

任务详情 → 口播草稿下面 → 「换个开头」。

- 选人群，点「出三版」，三档各出一条
- 点哪张卡，整篇口播就换成那版（钩子 + 五个镜头 + 行动号召）
- 卡片下方直接给出抖音和小红书标题，复制即用
- 改完记得点「保存草稿」

接口是 `POST /api/copy/versions`，规则生成，不花钱、秒出。要 AI 润色就点
「AI 生成」或「润色」走 `/api/copy/polish`。

## 加一条自己的钩子

在对应档的 `hooks` 数组里加一条，`tpl` 用现有变量就行：

```json
{ "tpl": "{region}这种{area}平，一层就一户", "need": ["region", "area"], "aud": ["any"] }
```

加完刷新页面就生效。真实爆款拆出来的句子直接往里塞，比一次写十条再挑更好用——
先跑十条视频，看哪条开头完播高，再补同类。

## 什么时候该上更重的东西

现在这套是「脚本定骨架、模型定语义」。下面这些是零件，不是主线，等对应的问题
真的出现了再上，否则只会把安装包撑大：

| 现象 | 才值得上的东西 | 代价 |
|---|---|---|
| 字幕跟口播抢拍或滞后 | whisperX 词级时间戳 | 多装一个模型，多跑一遍对齐 |
| 切点老是切在动作中间 | PySceneDetect 按画面变化找切点 | 多一个依赖，切点数变不可控 |
| 镜头选出来像走廊不像办公室 | Qwen3-VL 给画面打标签 | 要 GPU，选镜慢数倍 |
| 音色不像中介，像导航 | 豆包声音复刻（3 元/万字） | 按字符计费，要录样本 |

判断标准就一条：**问题出现了没有。** 没出现就不上。
