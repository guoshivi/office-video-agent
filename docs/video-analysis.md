# 视频分析与分镜编排

这份文档回答一个问题：**「AI 分析视频」到底由谁来做？**

## 一、先把模型的事实摆清楚

本机的 `embeddinggemma-2` 不是纯文本模型。它有三个塔：

```json
"architectures": ["EmbeddingGemma2Model"],
"text_config":   { "model_type": "embedding_gemma2_text", "hidden": 512  },
"vision_config": { "model_type": "gemma4_vision",         "hidden": 768, "layers": 16 },
"audio_config":  { "model_type": "gemma4_audio",          "hidden": 1024 }
```

视频工作台用 `mode='text_vision'` 加载它，`encode_media({'video': [clip]})`
把视频片段直接编码成向量。所以**它确实"看得到"视频**。

实测（`tools/vision_probe.py`，用一段产品视频切成 3 段）：

| 片段 | 「一个人在镜头前展示手里的产品」 | 「办公室前台、logo 墙」 | 「城市街道」 |
| --- | --- | --- | --- |
| clip_1 | **+0.7245** | +0.6006 | +0.5985 |
| clip_2 | **+0.7318** | +0.5988 | +0.6126 |
| clip_3 | +0.6867（「讲解护肤品」+0.6896） | +0.5564 | +0.5772 |

结论：视觉塔在工作，**能区分"画面里大致是什么"**，但分离度不高——
片段之间的相似度有 0.81–0.87，对「会议室 / 独立办公室 / 开放工位」这种
细粒度区分不可靠。

**它给的是向量，不是描述。** 嵌入模型不会告诉你"这张图糊了""逆光""构图不好"，
更不会写文案。

## 二、三层分工（推荐做法）

```
① 本地多模态向量（embeddinggemma-2）
   干什么：粗粒度场景归类、判断素材里到底有什么
   特点：本地、离线、复用工作台同一套权重和 GPU 锁，零额外成本
   不干什么：细粒度识别、质量判断、写文案

② 视频工作台
   干什么：把每句文案检索到最匹配的镜头 → 配音 → 字幕 → 贴纸 → 渲染
   关键：它按句切分文案，所以"一镜一句"的效果由**文案怎么分句**决定

③ WorkBuddy 多模态（我）
   干什么：看图复核画面质量、判断能不能用、按场景写文案
   特点：能说人话，能判断"这张糊了/逆光/拍到了不该拍的"
   代价：需要 WorkBuddy 在线，走会话有成本
```

所以不是"二选一"，也不是"两个都拿去理解视频"，而是：
**向量负责归类，工作台负责匹配与渲染，WorkBuddy 负责判断与写作。**

## 三、为什么不自建一个本地 VLM

- 显存：本机要留给出片和索引，再常驻一个 7B 级视觉模型会和它抢卡
- 收益低：房源视频的画面判断（有没有拍糊、有没有拍到门禁密码）
  用工作台同源的向量做粗筛已经能挡掉大部分，剩下的 Art 判断交给 WorkBuddy 更准
- 维护：多一个常驻服务就多一个会挂的东西；现在是一个进程 + 一个按需子进程

## 四、分镜怎么做

```bash
ova analyze V20261101-ABCDE          # 按时间切段，每段抽一张代表帧
ova storyboard V20261101-ABCDE --file board.json
ova render V20261101-ABCDE --wait
```

`analyze` 默认每 6 秒一段，最少 3 段最多 8 段，切分规则写死在
`app/shots.py` 里——**故意不用场景检测**：房源实拍镜头之间差异小，
固定时长切段更可预测，出了问题也容易解释。

`board.json` 格式：

```json
{ "shots": [
  { "index": 1, "label": "门头", "text": "F区F14，120平店面" },
  { "index": 2, "label": "工位区", "text": "大开间，二十个工位放得下" }
] }
```

约束（服务端会校验）：

- 一镜一句，**每句不超过 24 字**，超了会报错让你拆句——一屏放不下就会挤
- 句子顺序 = 镜头顺序，因为工作台是按句序渲染的
- 写完会合成 `script` 写回任务，原来的整段口播被覆盖

## 五、三个必须注意的坑

1. **原片自带硬字幕/水印会打架。** 实测素材里原片底部就有「怎么分辨真假呢」，
   我们烧的新字幕会和它叠在一起。真实拍摄要求中介关掉 App 自带的字幕，
   或者把我们的字幕位置上移（`subtitle_bottom` 调大）。
2. **不要编事实。** 文案里"层高四米二""采光通透"这类只能来自房源字段或画面
   里真的看到的，否则就是把中介往投诉上推。字段没有的，宁可不提。
3. **时长预算。** 中文口播约每秒 4 字，30 秒目标 ≈ 126 字。
   分镜句数 × 每句字数超过视频长度，配音会被压或被切。
